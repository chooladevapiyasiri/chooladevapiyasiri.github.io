Project Overview

Hospitality and multi-location restaurant chains often struggle with fragmented operational data, relying on isolated point-of-sale reports that fail to expose true profitability.

This project unites sales, ingredient inventory, recipe breakdowns, and labor schedules into a single source of truth—calculating exact food costs and labor margins at the granular order level.

Business Impact: Connects top-line revenue directly to underlying food and labor costs, enabling dynamic menu pricing, proactive inventory control, and optimized labor allocation during peak hours.

1. Database Architecture & Modeling

The warehouse is built on a 3NF relational schema (PizzaSalesDW) in SQL Server, structured around nine primary entities to enforce strict integrity constraints:

  • Sales & Logistics: Customers, Addresses, Orders, Items
  • Supply Chain & Operations: Ingredients, Inventory, Recipes
  • Workforce Management: Staff, Shifts, Rotations

2. Analytical Engine & Core Business Logic

To prevent downstream visual tools from running complex calculations, core business logic is processed at the database layer through four production SQL views:

Order Overview View: Consolidates order details, item breakdowns, customer records, and delivery locations into a single denormalized structure ready for fast reporting.

Stock & Ingredient Cost View: Deconstructs each sold item into its recipe components. Applies an itemized unit-cost formula to determine the true Cost of Goods Sold (COGS) per order:

Ingredient Cost = (Ingredient Unit Price / Unit Weight) * Recipe Quantity * Order Quantity

Inventory Analysis View: Aggregates real-time ingredient consumption across all historical orders and subtracts it from current warehouse inventory to display dynamic stock depletion levels.

Labor & Shift Analysis View: Tracks shift schedules and computes exact labor costs per team member while handling shifts spanning across midnight via time-difference logic:

Hours Worked = DATEDIFF(minute, Shift Start, Shift End) / 60.0
 Labor Cost   = Hours Worked * Hourly Wage

Key Insights & Trade-offs

  • 01
    Database Layer vs. BI Layer Processing: Embedding inventory formulas directly into SQL Server views reduced visual load times in Power BI and Tableau, preventing slow visual renders during interactive drill-downs.
  • 02
    Handling Complex Shift Logic: Using DATEDIFF minute-level precision resolved payroll calculation discrepancies for night-shift workers crossing past midnight.
  • 03
    3NF Integrity vs. Query Performance: Maintaining a strict 3NF schema guaranteed zero redundancy across ingredient catalog prices, requiring indexed database views to deliver real-time aggregate reporting.

Operational Recommendations & Future Work

1. Dynamic Reorder Triggers

Implement automated database alerts (SQL Server Agent tasks) when calculated stock levels fall below safety thresholds based on historical usage rates.

2. Automated Forecasting Integration

Connect predictive time-series models (e.g., Prophet or ARIMA) to order views to forecast next-week ingredient requirements and optimize vendor purchasing orders.

3. Real-Time Streaming Ingestion

Transition daily SSIS batch loads to real-time event ingestion (e.g., Kafka or Azure Stream Analytics) for live kitchen display system (KDS) monitoring.
